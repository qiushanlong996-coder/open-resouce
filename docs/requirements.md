# 新猿译码 需求文档

## 1. 项目概述

新猿译码是一个面向 Agent 开发者、AI 应用工程师、开源项目作者和技术团队的开源项目分享网站。平台核心目标是沉淀、展示、分发和协作讨论 Agent 开发相关项目，支持项目介绍、在线文档、代码展示、代码包下载、文档下载、媒体嵌入和文档级评论协作。

网站应兼顾专业性、性能和美观。整体视觉风格参考项目根目录 `design-md/apple` 中的 Apple 设计规范，强调简洁、克制、高级、阅读友好、内容优先、交互统一。

当前项目名称暂定为“新猿译码”。Logo 和正式域名由项目方后续提供。

## 2. 项目目标

1. 建立一个专门分享 Agent 开发项目的开源项目门户。
2. 支持项目从“发现、阅读、预览、讨论、下载、复用”的完整链路。
3. 提供接近在线协作文档的阅读与评论体验，支持选中文档内容后发起评论。
4. 支持富文本内容，包括代码块、图片、流程图、视频、表格、引用、任务列表等。
5. 支持代码在线展示和代码包下载，便于开发者快速评估与接入项目。
6. 提供文档下载能力，方便离线阅读、归档或企业内部流转。
7. 为后续扩展用户系统、项目审核、版本管理、搜索推荐、贡献者协作、API 开放等能力预留产品空间。

## 3. 目标用户

### 3.1 普通访客

普通访客主要用于浏览、搜索和下载项目。他们可能没有登录账号，也可能只是临时查看某个项目。

核心诉求：

1. 快速理解项目用途、亮点、技术栈和适用场景。
2. 在线阅读项目文档。
3. 预览关键代码。
4. 下载文档或代码包。
5. 观看项目演示视频或流程图。

### 3.2 注册开发者

注册开发者是平台主要活跃用户。他们会收藏项目、发表评论、参与文档讨论、关注项目更新。

核心诉求：

1. 对文档中的具体内容发起评论。
2. 参与评论回复和问题讨论。
3. 收藏项目，追踪项目更新。
4. 下载指定版本的代码包或文档。
5. 查看项目历史版本和更新说明。

### 3.3 项目作者

项目作者负责发布和维护自己的 Agent 开源项目。

核心诉求：

1. 创建和编辑项目主页。
2. 上传项目文档、代码包、封面图、演示视频等资源。
3. 维护在线文档内容。
4. 管理项目版本、下载文件和发布说明。
5. 回复用户评论和文档批注。
6. 查看项目访问量、下载量、收藏量、评论量等基础数据。

### 3.4 管理员

管理员负责平台内容治理、用户管理、项目审核和资源合规。

核心诉求：

1. 审核项目发布与更新。
2. 管理违规内容、评论和资源文件。
3. 配置分类、标签、首页推荐和精选项目。
4. 查看平台运行数据。
5. 处理用户举报和内容下架。

## 6. 核心功能需求

## 6.1 首页

首页用于建立平台第一印象并引导用户发现优质 Agent 项目。

功能要求：

1. 展示平台定位和核心价值。
2. 展示精选 Agent 项目。
3. 展示热门项目、最新项目、编辑推荐项目。
4. 支持按方向快速进入分类，例如：
   - Multi-Agent
   - RAG Agent
   - Workflow Agent
   - Browser Agent
   - Coding Agent
   - Data Agent
   - Voice Agent
   - Tool Calling
   - Agent Framework
5. 提供全局搜索入口。
6. 展示项目关键指标：Star 数、下载量、更新时间、技术栈、许可证。
7. 展示近期更新或社区动态。

体验要求：

1. 首屏应简洁高级，突出平台名称和项目内容，不做传统营销式堆叠。
2. 项目卡片应信息密度适中，方便快速扫读。
3. 交互颜色统一使用 Apple 风格主蓝色。
4. 首页需适配桌面端、平板和移动端。

验收标准：

1. 用户进入首页后 5 秒内能理解网站用途。
2. 用户能在首页进入项目详情、项目列表、搜索结果。
3. 首页加载首屏内容应快速，无明显空白等待。

## 6.2 项目列表与筛选

项目列表用于集中浏览和筛选 Agent 开源项目。

功能要求：

1. 支持分页或无限滚动加载项目。
2. 支持关键词搜索。
3. 支持分类筛选。
4. 支持标签筛选。
5. 支持技术栈筛选，例如 React、Go、Python、LangChain、LlamaIndex、AutoGen、OpenAI、MCP 等。
6. 支持许可证筛选，例如 MIT、Apache-2.0、GPL、BSD 等。
7. 支持排序：
   - 最新发布
   - 最近更新
   - 最多下载
   - 最多收藏
   - 最多评论
   - 推荐优先
8. 支持项目状态标识：
   - 活跃维护
   - 实验项目
   - 已归档
   - 生产可用
9. 支持列表视图和卡片视图。

项目卡片字段：

1. 项目名称。
2. 项目简介。
3. 封面图或项目图标。
4. 分类。
5. 标签。
6. 技术栈。
7. 作者。
8. 最近更新时间。
9. 下载量。
10. 收藏量。
11. 许可证。

验收标准：

1. 筛选条件组合后结果正确。
2. 清空筛选后恢复默认列表。
3. 无结果时展示清晰的空状态。
4. 移动端筛选器可正常收起和展开。

## 6.4 在线文档

在线文档用于展示项目说明、教程、API 文档、部署指南和设计说明。

功能要求：

1. 支持多级文档目录。
2. 支持文档章节导航。
3. 支持 Markdown 或富文本内容展示。
4. 支持标题、段落、列表、表格、引用、任务列表。
5. 支持代码块高亮。
6. 支持图片嵌入。
7. 支持流程图嵌入。
8. 支持视频嵌入。
9. 支持附件链接。
10. 支持文档内锚点跳转。
11. 支持全文搜索或当前文档搜索。
12. 支持复制标题链接。
13. 支持复制代码块。
14. 支持目录自动生成。
15. 支持文档下载。

交互要求：

1. 左侧显示文档目录。
2. 中间显示正文内容。
3. 右侧显示当前页面大纲和评论面板。
4. 小屏幕下目录和评论面板应可收起。
5. 代码块应提供语言标识和复制按钮。
6. 图片点击后支持预览放大。
7. 视频应支持播放、暂停、全屏等基础能力。
8. 流程图应清晰渲染，移动端可横向滚动或缩放查看。

验收标准：

1. 文档内容能稳定渲染。
2. 代码块、图片、流程图和视频都能正确展示。
3. 文档目录点击后能滚动到对应章节。
4. 文档内容过长时页面滚动顺畅。

## 6.5 文档选区评论

文档选区评论是平台的重要协作能力，体验参考钉钉文档、飞书文档或 Notion 评论。

功能要求：

1. 用户可在在线文档中选中一段文字。
2. 选中文本后出现评论入口。
3. 用户点击评论入口后可输入评论内容。
4. 评论提交后，该文本区域应显示评论锚点或高亮标记。
5. 点击评论锚点可打开对应评论线程。
6. 一个选区可对应一个评论线程。
7. 一个评论线程支持多条回复。
8. 评论支持编辑、删除、回复、解决。
9. 评论支持已解决和未解决状态。
10. 评论支持定位回原文。
11. 文档右侧评论面板应展示当前文档所有评论。
12. 评论应记录创建人、创建时间、更新时间。
13. 作者和管理员可管理评论。
14. 评论创建、回复、编辑、删除和解决状态变化应实时推送给当前在线阅读该文档的相关用户。
15. 用户在同一文档页内无需刷新即可看到新评论和新回复。

评论权限：

1. 未登录用户可查看公开评论。
2. 未登录用户不能发表评论。
3. 登录用户可发表评论和回复。
4. 评论作者可编辑或删除自己的评论。
5. 项目作者可解决或隐藏评论。
6. 管理员可删除违规评论。

选区锚定要求：

1. 评论应尽量绑定到稳定的文档位置。
2. 当文档内容更新后，历史评论应尽量保留定位。
3. 若原选区内容发生变化，应展示“位置可能已变化”的提示。
4. 评论面板中应可看到被评论的原文摘录。

验收标准：

1. 用户选中文本后能创建评论。
2. 评论创建后能在原文位置看到标记。
3. 点击标记能打开正确评论线程。
4. 评论线程支持回复和解决。
5. 文档刷新后评论仍能恢复显示。

## 10. 视觉与交互需求

设计风格采用 Apple 设计规范，结合开源技术网站的信息密度。

视觉原则：

1. 内容优先，减少装饰。
2. 主色统一使用 Apple 风格蓝色。
3. 页面以白色、浅灰、近黑色为主要背景。
4. 重要页面采用大留白和清晰层级。
5. 后台和列表页面应更偏工具化，信息密度更高。
6. 卡片不应过度阴影化。
7. 按钮以胶囊形主按钮为主。
8. 文档阅读区域应清爽、舒适、长时间阅读不疲劳。

交互原则：

1. 所有主要操作应有清晰反馈。
2. 下载、提交、上传等操作需要 loading 状态。
3. 错误提示应明确可理解。
4. 空状态应提供下一步建议。
5. 移动端应保证基础功能可用。
6. 文档评论、代码复制、目录跳转等高频操作要轻量顺滑。

响应式要求：

1. 桌面端优先支持 1440px、1280px、1024px。
2. 平板端支持 834px 左右宽度。
3. 移动端支持 390px、430px 常见宽度。
4. 文档页在小屏下应收起侧栏。
5. 表格、代码块和流程图在小屏下允许横向滚动。

验收标准：

1. 页面整体风格与 Apple 设计规范方向一致。
2. 核心页面在桌面端和移动端不出现明显错位。
3. 文字不溢出容器。
4. 按钮和交互元素触控区域不小于 44px。

## 11. 性能需求

前端性能：

1. 首页首屏加载应尽量快。
2. 图片应懒加载。
3. 视频不应默认自动加载完整文件。
4. 文档内容较长时滚动应流畅。
5. 代码高亮和流程图渲染不应阻塞主线程过久。
6. 列表页应支持分页或虚拟滚动。
7. 静态资源应支持缓存。

后端性能：

1. 项目列表查询应支持分页。
2. 搜索应支持索引。
3. 下载统计不应阻塞下载链路。
4. 评论查询应按文档或项目分页加载。
5. 大文件上传和转码应异步处理。
6. 高频读取内容应支持缓存。

目标指标：

1. 首页首屏主要内容在普通网络下 3 秒内可见。
2. 项目列表查询常规场景 500ms 内返回。
3. 文档页正文常规场景 1 秒内可展示。
4. 评论提交常规场景 1 秒内反馈。
5. 下载接口应能稳定处理大文件。

## 12. 安全需求

账号安全：

1. 密码必须加密存储。
2. 登录态应安全管理。
3. 敏感接口需要鉴权。
4. 管理员接口需要额外权限校验。

内容安全：

1. 富文本内容需要防 XSS。
2. Markdown 渲染需要过滤危险脚本。
3. 上传文件需要类型校验。
4. 外链视频和图片需要安全策略。
5. 评论内容需要敏感词或违规检测扩展能力。

下载安全：

1. 下载链接需要权限校验。
2. 私有资源不得通过静态路径直接暴露。
3. 文件路径不能由用户输入直接拼接。
4. 下载行为应记录审计数据。

验收标准：

1. 未授权用户不能访问受限接口。
2. 常见 XSS 内容不会被执行。
3. 非法文件类型不能上传。
4. 管理操作有审计记录。

## 19. 一期上线时间要求

3. 可延期：Git 仓库同步、在线文档编辑、多语言、公开 API、AI 辅助能力、推荐系统。
